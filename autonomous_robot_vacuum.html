RASPBERRY PI ROBOTICS PROJECT

Autonomous Robot Vacuum

Build an indoor autonomous mobile robot using Raspberry Pi 5 and ROS 2 Jazzy. The robot uses LiDAR to map rooms, localize itself and navigate around furniture. Cleaning brushes and suction can be added after autonomous navigation is working.

Explore Project

PROJECT OVERVIEW

About This Project

This Autonomous Robot Vacuum uses a Raspberry Pi 5 as its main computer. ROS 2 Jazzy provides the robotics software framework for sensor communication, robot control, mapping and navigation.

A LiDAR sensor publishes laser scan data. SLAM Toolbox uses the scan and odometry information to create a map of the indoor environment. Nav2 uses the map and robot pose to plan paths and navigate toward selected destinations.

The project is organized into separate Python modules for motor control, encoders, sensors, safety monitoring, odometry and navigation. The initial stage focuses on mapping and safe movement. Vacuum and brush hardware are kept as a separate later stage.

WHAT IT CAN DO

Project Features

LiDAR Obstacle Sensing

Receive laser scan measurements to detect walls, furniture and nearby objects.

Room Mapping

Use SLAM Toolbox to build a two-dimensional map while the robot explores an indoor area.

Autonomous Navigation

Use Nav2 to plan a route and navigate to a selected goal on the saved map.

Wheel Odometry

Use wheel encoder measurements to estimate the robot's movement.

Safety Monitoring

Monitor bumper switches and ultrasonic sensors. Stop movement when an emergency or invalid sensor condition is detected.

Expandable Cleaning System

Add separately powered vacuum and brush motors after the navigation platform has been tested.

HARDWARE REQUIREMENTS

Components Required

  • Raspberry Pi 5
  • Compatible power supply for Raspberry Pi 5
  • 2D LiDAR sensor (select the driver for the exact model)
  • Differential-drive robot chassis
  • 2 DC geared motors with wheel encoders
  • Motor driver compatible with the selected motors
  • Motor battery pack with suitable protection
  • IMU sensor
  • Front and rear ultrasonic distance sensors
  • Front and rear bumper switches
  • Jumper wires, connectors and mounting hardware
  • Optional vacuum motor and brush motor for the later cleaning stage
Do not connect motors directly to Raspberry Pi GPIO pins. Use a suitable motor driver and a separate motor power supply. Connect the grounds as required by the driver manufacturer's wiring instructions. Check all voltage levels before wiring.

SOFTWARE REQUIREMENTS

Software and ROS 2 Packages

  • Ubuntu 24.04 64-bit for Raspberry Pi 5
  • ROS 2 Jazzy
  • Python 3
  • colcon build tools
  • ROS 2 Nav2
  • SLAM Toolbox
  • robot_state_publisher
  • robot_localization
  • gpiozero and a compatible Raspberry Pi GPIO backend
  • RViz2 for visualization

Install ROS 2 packages using the Ubuntu and ROS 2 package installation instructions. The Python requirements file contains additional Python dependencies; ROS 2 packages should be installed through the ROS/Ubuntu package manager, not replaced with pip packages.

HOW IT WORKS

Step-by-Step Operation

  1. Install Ubuntu 24.04 64-bit and ROS 2 Jazzy on Raspberry Pi 5.
  2. Assemble the differential-drive chassis and connect the motor driver, encoders and sensors.
  3. Configure GPIO pins, encoder pins, wheel dimensions and encoder resolution.
  4. Install dependencies and build the ROS 2 workspace using colcon.
  5. Install the hardware-specific LiDAR driver for your sensor model.
  6. Start robot nodes and verify sensor topics, odometry and TF frames.
  7. Start SLAM Toolbox and move the robot slowly to create a map.
  8. Save the map and configure Nav2 for the measured robot dimensions.
  9. Test navigation at low speed in a clear, supervised area.
  10. Add and test cleaning motors only after navigation and emergency-stop systems work reliably.

SYSTEM ARCHITECTURE

How the ROS 2 Modules Work Together

Hardware Layer

Motor control, wheel encoders, LiDAR, IMU, ultrasonic sensors and bumper switches.

Sensor Processing

Publish standardized ROS 2 messages for laser scans, IMU readings, distance measurements and bumper events.

Mapping and Localization

SLAM Toolbox builds the map. Odometry and TF provide robot movement information.

Navigation

Nav2 plans and controls movement. The velocity safety layer can block motion during an emergency.

HARDWARE CONNECTIONS

Connection and Configuration Guide

This project does not assume universal GPIO assignments. The supplied configuration uses placeholder pin values until the actual motor driver, encoder, ultrasonic sensor and bumper wiring have been selected.

Device Connection / Interface Configuration
LiDARUSB or supported interfaceDevice path and baud rate in the LiDAR driver
IMUI2C or supported interfaceAddress and hardware driver configuration
Left and right motorsMotor driver inputsGPIO values in motor-control configuration
Wheel encodersEncoder output channelsGPIO pins and ticks per wheel revolution
Ultrasonic sensorsTrigger and echo pinsGPIO values in ultrasonic.yaml
Bumper switchesSwitch input and groundGPIO values in bumper.yaml
Vacuum and brush motorsSeparate suitable driver or switching circuitDisabled until the cleaning stage is installed
Raspberry Pi GPIO uses 3.3V logic and is not 5V tolerant. Never connect a 5V ultrasonic echo output directly to a Raspberry Pi GPIO input. Use a suitable level shifter or voltage divider. Confirm the electrical interface of every sensor before connecting it.

IMPORTANT INFORMATION

Setup and Safety Notes

  • The supplied LiDAR and IMU processing nodes expect hardware-specific driver nodes to publish their input topics. Select and configure drivers for the exact sensor models.
  • Configure all GPIO pins and encoder resolution before enabling motor movement. Placeholder values are not working hardware pin assignments.
  • Calibrate wheel radius, wheel separation, robot size and sensor mounting positions using the assembled robot.
  • Verify that only one node publishes each required TF transform. Incorrect or duplicate transforms can break mapping and navigation.
  • Review and test ROS 2 topic remappings and message types for the installed Jazzy/Nav2 version before running autonomous movement.
  • Test the emergency stop, bumper switches and sensor failure behavior with the wheels raised and at low speed.
  • Keep the robot supervised during all tests. Software safety functions do not replace a physical power disconnect or emergency stop.
  • Disconnect power before changing wiring or working on the motor driver.
This is a project starter package, not a pre-calibrated, plug-and-play vacuum robot. The exact LiDAR model, IMU, motor driver, encoder specification and wiring are needed to complete hardware integration and validation.
